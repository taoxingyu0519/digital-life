# 人脸与登录解耦、逐消息人物归档

开始：2026-10-28。任务：AIRI-045。源于用户反馈：不稳定的人脸登录令舞台和右上角频繁跳动，目标是连续聊天并按人保存原文。

登录账户与人物归档分离。`userId` 始终来自认证，短租期只决定 `archiveUserId`。匿名档案先保存合格特征与永久 UUID；确认姓名后保留 ID 和早期记录，持久行为规则引导适时换措辞询问。

普通文字、部分/最终语音和助手回合捕获同一归属，任务结果沿用任务归属。气泡上方用10px、低强调的角色-人物标签显示归档对象。姓名目录按UUID更新，不用名字作主键。

另以生成用例复现换人后的主动文字/语音问候误用上一人ID，修正为当前人物；普通回复仍跟随原话轮。5项相关场景通过。字号与移动对齐由实际页面脚本测量，组件夹具验证姓名和ID绑定。

主机继续保存人物和有界交流，完整原文复用当前浏览器数据库。支持原会话归属与逐消息归属共存，检索/整理/导出过滤同一对象，混合会话清除只删除目标人物。没有新增插件、账号或跨设备完整聊天同步。

测试先复现 `userId` 随人脸改变和缺少逐消息归属。后续发现部分语音与异步回复需固定归属、Vue Proxy 不能穿过序列化边界、姓名确认不能复用被隐藏的记忆投影来决定归属，分别修正并回归。`social.recipient` 与 `profile` 分别负责归属和有界记忆。

实际4173舞台用生成消息验证桌面/390px标签、连续四条消息、右上角陌生人、启停重启与休眠记忆导航。真实人物库先做私密备份，未删除真实人物做测试。真人识别、多人麦克风和模型问名话术仍另验。
