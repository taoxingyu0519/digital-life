# Wiki 读取与维护流程

Wiki 保存长期项目知识，任务账本保存工作进度。两者通过任务编号与源码证据连接。
本项目报告统一使用中文。技术名称、代码、命令、路径和原始错误保留原文，必要时附中文解释。
报告必须说明真实服务验证、模拟测试及未验收范围。“完整链路”要写明包含哪些实际步骤。
新对话先读首页，再检索问题。不要默认加载全部文章、任务事件或完整源码清单。
读取看板时先提取任务编号、标题和状态，再展开当前任务的说明与事件。
读取改动时先看 Git 文件状态，再按相关路径读取 diff。

## 开发流程

1. 读取任务看板与当前改动，在管理服务新增或更新任务。
2. 从首页或 find 命中一到两篇专题。
3. 查看待复核提示，读取相关源码与测试。
4. 修改实现后，更新涉及职责、接口和数据流的专题。
5. 按工作区规则更新原开发文档。应用变更运行 `scripts/test-airi-delivery.ps1 -Task <task-id>`，保留语音、身份、档案、会话、采集与启停旧功能基线；失败不得报告回归通过。实际页面启停和设置/长期记忆导航另验，设备或模型缺失明确记录。
6. 新增开发记录，提炼有复用价值的经验或决策。
7. 人工核对每篇受影响的专题，再用 review 记录证据指纹。
8. 运行 Wiki check 和目录同步，在任务记录结果后交付。

## 命令

从工作区根目录初始化已有 Node：

```powershell
. ./scripts/airi-env.ps1
& $AiriNode ./scripts/project-wiki.mjs find '摄像头数据怎样进入回答'
& $AiriNode ./scripts/project-wiki.mjs show visual-social
& $AiriNode ./scripts/project-wiki.mjs check
# 人工读过源码和文章后，填写本轮任务与核对说明
& $AiriNode ./scripts/project-wiki.mjs review visual-social --task AIRI-013 --note '核对帧协议和投影边界'
& $AiriNode ./scripts/generate-project-index.mjs
```

find 搜索标题、摘要与关键词，不展开正文。没有命中时调整词语或对 catalog 使用 rg。
show 只读指定文章。check 核对结构、本地链接、来源路径和证据变化，有错误或待复核时退出非零。
review 只记录人工核对声明与指纹，不运行测试，也不证明测试通过。
review 一次处理一篇。新增专题必须先加入 catalog.json，再核对其来源。

## 目录与信息上限

| 层级 | 内容 | 维护约束 |
| --- | --- | --- |
| 首页 | 问题路由与边界 | 保持短小，不复制详细算法 |
| 专题 | 模块、流程和算法 | 一篇一个职责，附源码与验证入口 |
| 成长 | 历史、原因和经验 | 历史不覆盖当前事实，标明被替代方案 |
| 开发记录 | 单轮目标、变更、证据和交接 | 使用模板，保留任务编号 |
| catalog.json | 标题、摘要、关键词和来源 | 人工维护检索信息，不放正文 |
| evidence.json | 核对时间、任务、说明及 SHA256 | review 命令维护，禁止盲目刷新 |
| index.md 与 index.json | 当前目录与证据状态 | 自动生成，不人工改写 |

正文默认控制在约三千中文字符。超长后拆分专题，更新首页与 catalog。
此处长度是阅读约束，不是精确 tokenizer 测量。检索输出的条数限制不能保证固定 token 节省比例。
目录同步监测 Wiki 内容，自动生成证据状态，但不刷新已核对的指纹。
源文件或文章变化后标为“待复核”。缺少基线显示“未核对”。来源删除会显示错误。

## 增长与冲突

新记录从 [开发模板](templates/session.md) 开始。新专题从 [专题模板](templates/topic.md) 开始。
只有可复用因果知识进入经验页，命令输出留在对应报告或任务。
当前事实与源码冲突时先复核源码。用户最新要求决定产品目标，已验证源码决定实现事实。
记录新的证据日期和任务，历史方案保留为“被替代”，不要偷偷删除决策原因。
管理工具只读 Wiki。修改通过编辑文件完成，防止 UI 写入与 Codex 编辑竞争。

## 问答和隐私

回答采用“当前结论、数据路径或规则、源码证据、验证限制”的顺序。
项目自我了解指可追溯的工程知识。没有证据时，不声称具备意识、训练升级或全部验收。
不得保存 Key、令牌、私人入口、人物姓名、照片、特征模板或私人发言。
需要示例时使用抽象角色和生成数据。根目录 Wiki 不在 airi Git 内，需随工作区备份。
