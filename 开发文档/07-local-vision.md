# 本地社交视觉与主动交流

## 当前行为

2026-10-28，AIRI-045：人脸不再绑定登录或切换主舞台会话。有效单人脸仅提供逐消息归档对象；匿名档案可在姓名之前保存加密特征并分配永久 UUID，确认姓名后只更新显示名称。完整原文沿用当前浏览器聊天数据库，主机保留人物与有界交流记忆。未命名时由持久行为规则引导自然询问；多人、过期或撤权不借用旧归属，聊天继续。旧文中“识别后切换账户”的描述已由本条替代，详见[交付报告](../airi/docs/ai/reports/2026-10-28-message-person-archive.md)。

用户提供的 `AIRI-local-vision-4090-codex-spec-v2.0.zip` 包含规范、契约和测试矩阵，没有可运行服务源码。
本项目已实现本地视觉服务与 AIRI 对话接入。2026-09-30 的最新要求取代原规范的默认关闭和强制手工登记。

- 默认主动模式，主窗口自动请求摄像头并持续本地识别。主动／被动按钮在舞台左下角。
- 模式保存在本机。被动模式释放摄像头，取消尚未完成的主动思考与输出，普通输入继续可用。
- 见到稳定在场的人主动问候。陌生人会被问“你好，陌生人！你叫什么名字？”
- 用户通过真实文字或最终语音转写介绍自己，智能体自动把当前清晰人脸与姓名关联。
- 十个一致清晰样本自动建档。正面、左右角度的照片与模板在交流中逐渐补充，不要求手工登记或校准。
- 确认人物后，按人物和当前角色记忆真实交流。主动闲聊引用已有记忆，不能编造共同经历。
- 默认主动闲聊最短间隔五分钟，可选一、三、五、十、三十分钟。用户活动后至少安静一分钟。
- 用户实际说话、等待转写或助手回答时暂缓主动输出，空闲麦克风和空闲通话不会一直阻止问候。

“察言观色”目前输出可见的头部、嘴角、手部动作和不确定性，不能仅凭表情断言心理状态。
多人或归属不明确时不学习姓名，不把说话内容强行归给某个人。轨迹 ID 不是持久身份。

## 启动与关闭

在工作区根目录执行：

```powershell
# 已安装环境不必重复下载
./scripts/vision.ps1 doctor
./scripts/start-airi.ps1

# 单独控制视觉服务
./scripts/vision.ps1 start
./scripts/vision.ps1 stop
```

`start-airi.ps1` 在本地视觉环境存在时自动启动服务，然后打开 Web 开发服务。
Python 单独启动时不打开摄像头。AIRI 主窗口按当前模式请求浏览器摄像头。
本机使用 `http://127.0.0.1:5173` 或 `http://localhost:5173`，预览端口为 4173。
笔记本使用已有双端口 SSH 隧道，将本机 5173 和 18765 分别转发到工作站。隧道连接由 `AIRI-010` 跟踪。
直接使用非安全的局域网 IP 页面不属于已支持摄像头入口。

首次访问仍需浏览器摄像头授权。程序不能绕过浏览器或系统的设备权限。
摄像头由选举出的主窗口持有。工作坊和本地视觉共享摄像头锁，旧周期视觉任务不能同时采集。
切换角色、会话、摄像头或人脸权限时释放旧实例，主动模式随后重新绑定。
服务失败按间隔重试。权限被拒绝时停止自动重试，允许权限后切换模式重新启动。
界面区分权限被拒绝、未发现摄像头、摄像头无法读取和服务连接失败。

Python 环境在 `.runtime/vision-venv`。Node 环境由 `scripts/airi-env.ps1` 初始化。
日志位于 `.runtime/vision-service*.log`，停止脚本核对项目 PID 和启动时间。
界面显示实际 `cpu` 或 `cuda`，模型未加载不会显示已就绪。

## 自然认识人和记忆

1. 在有摄像头的浏览器打开舞台，保持一人清晰可见。
2. 收到问候后，直接回答“我叫小明”或“叫我阿明”。无需填写登记表。
3. 保持正常交流。积累十个一致样本后自动创建档案，轻微左右转头会补充其他角度。
4. 视觉设置页可查看当前档案、角度数量、已有交流记忆及学习进度。
5. 再次出现并通过多帧确认后，智能体使用已认识的称呼，主动询问以前聊过的话题。

回答归属要求当前帧有效期不超过两秒、单人、脸部通过质量检查且没有身份歧义。
登记照片要求人脸短边至少 96 像素、清晰度至少 70，并过滤曝光异常及过大转头。
普通识别允许短边至少 64 像素、清晰度至少 35 的画面。这类帧只用于识别，不补充照片或模板。
清晰度使用灰度 Laplacian 方差。学习窗口最多三分钟，不保存失效半成品。
初始社会交互匹配使用余弦相似度至少 0.55、候选间隔至少 0.10，并要求两秒内三次有间隔的确认。
已确认的同一轨迹允许相似度短暂降至 0.50，仍要求候选唯一。校准后的保持阈值最多比确认阈值低 0.05。
模糊或转头时最多保留 1.5 秒最近确认。不同人脸、多人、交叠或超时撤销确认，重新积累证据。
短暂检测漏帧不删除所有内部身份状态，但该帧不向对话输出人物，也不将话语归给消失的人。
重复自我介绍与十个新样本同时高度吻合唯一已有档案时复用人物 ID，避免同一人双档案产生歧义。
复用要求最佳余弦中位数至少 0.90、最小值至少 0.85、档案间隔至少 0.10，姓名相同本身不触发合并。
这些阈值是保守起点，不代表已经取得真人准确率结论。
已有本机校准只能提高初始阈值。独立校准和留出测试用于质量评估，不阻止普通自然介绍。

只保存真实用户的最终输入，语音转写片段不重复保存。每个人物与角色最多八十条，给模型最多最近八条。
语音完整识别假设和最终结果替换已有文本，只有增量事件追加，防止纠正姓名被重复拼接入库。
记忆是用户说过的话，并非已验证事实。模型收到有界引文，不能把引文当成系统指令。
人物离开、出现多人、切换角色或会话后，旧姓名、照片和记忆不能继续归给新对象。
说“不要记住我”会删除当前匹配的本地档案，包括模板、照片和记忆，并停止该轨迹继续学习。
视觉页“删除档案、照片和记忆”提供显式删除入口。

## 语音和主动思考

本地识别、姓名学习及文字问候不依赖聊天模型。自然自由对话和生成新话题需要现有聊天或实时模型服务。
没有配置时界面明确提示，不能把固定文字模板算作模型已经配置成功。

主动思考复用当前角色与已配置聊天模型，最多两句，一个在途请求，十五秒超时，不调用工具。
无人或冷却期内不持续调用云端模型，每帧视觉推理仍在本机执行。
主动事件作为本地助手消息显示，不伪造用户发言。静音只保留文字，停止按钮取消待输出内容。

已有豆包实时语音配置时，见到单人可自动接入一次通话，听取实际回答。
正常 ASR 麦克风已经开启时不抢占它。自动通话在无人三十秒、后台、被动模式或十分钟上限时结束。
手动挂断和时长上限不会在同一次持续在场中自动重连。需要时可以手动再开始通话。
主动发声使用官方 `speech_text_buffer.commit`，视觉文字和记忆使用 `session.update`，都经过现有 Eventa 网关。
没有增加新服务账号、密钥或付费额度。真实服务可用性与计费资格仍由用户已有配置决定。

## 权限和数据

本轮按用户明确要求，默认主动、允许本地人脸学习、文字上下文、称呼与问候。默认禁止摄像头图片外发。
已有显式权限选择保留，所有选择仅存本机，不进入云同步配置。

| 开关 | 用途 |
| --- | --- |
| 主动／被动模式 | 开启持续本地采集，或释放摄像头并等待输入 |
| 人脸登记与匹配 | 自然建档、匹配和补充角度 |
| 当前观察文字 | 聊天及实时语音使用当前人数、物体、动作和有界个人记忆 |
| 已确认称呼 | 聊天、实时语音和语音合成可使用已确认人名 |
| 摄像头图片 | 手动点击“看一下”时发送完整画面给选定视觉服务商 |
| 主动问候 | 调度问候、闲聊与已有实时语音的见面接入 |

完整画面只走本机 LV01 帧通道，单帧在途，不录制摄像头视频。
图像外发需独立开启并点击按钮。“包含最近几帧”最多缓存三秒六帧，撤销权限立即清空。
已发送的外部请求不能收回。撤销、停止及代际变化拒绝待处理和迟到结果。

私人数据位于 Git 忽略的 `airi/.local/vision/`，Vite 拒绝通过文件接口访问。
SQLite `people` 存本地姓名与 DPAPI 模板，`photos` 存每个角度的人脸裁剪，`encounters` 存相遇时间。
`memories` 按人物、角色和真实事件 ID 保存加密文字，`revoked` 防止已删除身份恢复。
模板、照片、记忆正文使用当前 Windows 用户的 DPAPI 加密。不同 Windows 用户不能直接解密。
姓名及相遇时间仍是本机数据库字段。不要把私人目录、真实素材或凭据上传到任务板、版本库或共享截图。

视觉产生的助手消息标记 `localVisionDerived`，保留本地显示，但排除后续模型历史及云端消息同步。
真实用户主动输入继续遵循原聊天规则。人脸识别无活体检测，不用于账号认证或访问授权。
请告知画面内其他人本地学习与存储方式，参与者可要求停止记忆并删除档案。

## 模型部署与可选找物

常态视觉使用 YOLOX、ByteTrack、MediaPipe、YuNet 与 EdgeFace S。
SFace 保留为登记模板编码器，只在自然建档或补充角度时按需使用。原档案与记忆保留。

### 摄像头驱动目光和头部

Web 舞台已将鼠标跟随换为人脸位置跟随，支持陌生人，不要求先记住姓名。
沿用现有 YuNet 与 ByteTrack，不启动第二条摄像头或新模型。
画面中优先注视所选主目标，其次保持原轨迹，首次多人入镜时选最大可见脸。
水平按自拍镜像方向转换，位置平滑并过滤小幅抖动。Live2D 通用动作模式和 VRM 都接收同一目标。
VRM 头部约限制到水平 ±17°、垂直 ±11°，眼睛先跟随，头部稍慢。
静止脸持续有效，短暂漏检容忍 250ms。画面年龄加往返耗时超过 500ms 就停止跟随。
关闭主动模式、失去采集拥有者或撤销人脸／观察权限后立即释放，恢复原有闲置行为。
现有手工动作控制仍保留优先权。Magic、MMD、Spine 和静态立绘没有新增人脸头部控制。

笔记本刷新后开启主动模式，左右上下移动并在中心停留超过一秒，再遮脸或离开、切换被动模式。
本轮自动验证不包含真人方向、幅度或整机帧率验收。记录见 `airi/services/local-vision/reports/validation.face-gaze.md`。
首次部署及可选 Grounding DINO：

```powershell
./scripts/vision.ps1 install
./scripts/vision.ps1 install-cuda
./scripts/vision.ps1 prepare

# 可选找物，不影响社交视觉
./scripts/vision.ps1 install-grounding
./scripts/vision.ps1 prepare-grounding
./scripts/vision.ps1 stop
./scripts/vision.ps1 start
```

DINO 依赖和权重较大。模型只加载固定本机文件，不执行 remote code，不在推理请求中下载。
支持最多八个标签、单个在途请求，显存门槛拒绝低优先级找物请求，中文仅支持小词典。
当前 DINO 仍未准备与真实验收，不影响常态认识人与问候。

## 持续人脸识别开源调研（2026-10-01）

持续识别由检测、跟踪、选帧、特征提取、身份确认与短时保持共同实现。
单帧验证准确率不能证明连续视频不跳名，也不能证明陌生人不会被错认。

| 候选 | 已核查的一手资料 | 对 AIRI 的用途与限制 |
| --- | --- | --- |
| [EdgeFace](https://github.com/otroshi/edgeface) | 2024 年模型，官方提供权重。XS 为 1.77M 参数、154 MFLOPs，S 为 3.65M 参数、306 MFLOPs。代码 BSD-3-Clause | 优先作为轻量识别候选，与现有 SFace 做同录像对比。参数小不自动代表本机延迟低 |
| [FaceLiVTv2](https://github.com/novendrastywn/FaceLiVT) | [2026-04 论文](https://arxiv.org/abs/2604.09127)，仓库仍标 TBIOM 审稿中。官方已发布 XS/S/M/L 权重，S 为 4.62M 参数、作者表中 179M 运算 | 新的 CNN 与线性注意力混合模型。移动端数据有潜力，Windows ONNX、算子和识别质量还需实测 |
| [AdaFace](https://github.com/mk-minchul/AdaFace) / [CAFace](https://github.com/mk-minchul/caface) | AdaFace 的训练损失考虑图像质量。CAFace 对多帧特征做可增量的聚类与聚合，官方有权重 | 改善低质量帧与视频判断。完整 CAFace 权重绑定 AdaFace 特征，不能直接套在 SFace 上，默认也不保证更省算力 |
| [OC-SORT](https://github.com/noahcao/OC_SORT) / [Deep-OC-SORT](https://github.com/GerardMaggiolino/Deep-OC-SORT) | 前者是运动跟踪，后者结合外观信息增强多人跟踪 | 适合改善轨迹连续性。行人 ReID 与认识人的人脸姓名不同，多人遮挡收益需实测，单人先保留 ByteTrack |
| [InsightFace / SCRFD](https://github.com/deepinsight/insightface/blob/master/model_zoo/README.md) | 有多个检测与识别模型包，buffalo_sc 约 16 MB。官方模型库标明预训练模型仅限非商业研究 | 可作为成熟检测与识别对照。代码许可与权重许可分别核查，不能用代码 MIT 替代权重使用范围 |

工程建议：保持摄像头和跟踪活跃，陌生或不确定时较频繁提取特征，稳定确认后降低频率。
例如特征提取从每秒五次降至一次，稳定阶段调用次数减少 80%，这不是整机功耗降低 80% 的结论。
结合姿态、模糊度、曝光和多角度样本选择较清晰帧。短时保持不得跨新人物或长期失去脸部证据。
先对比现有 SFace 与 EdgeFace XS/S，再将 FaceLiVTv2-S 作为较新候选。
评估记录每分钟姓名跳变、陌生人误认、再次确认时间、CPU/GPU、温度和耗电，不能只比较 LFW。
本次调研已进入实施，2026-10-01 在本机部署 EdgeFace S、质量加权多帧证据与稳定阶段降频。
切换模型时保留姓名、照片与交流记忆，用照片重新提取独立版本的特征，不能混合新旧向量。

## 已部署的轻量识别与降频（2026-10-01）

本项目用于非商业、非盈利科学研究。EdgeFace 原始项目 BSD-3-Clause 与 ONNX 转换项目 MIT 许可分别保存。
权重来源为 [EdgeFace ONNX](https://github.com/yakhyo/edgeface-onnx)，作者从原始模型导出。本次没有验证其与 PyTorch 权重的逐元素一致性。
使用现有 ONNX Runtime、OpenCV 和 ByteTrack，没有安装新的推理依赖或模型服务账号。

| 本机对比，CPU 特征提取 | 中位数 | P95 | 已有三角度裁剪的最低跨角度相似度 |
| --- | --- | --- | --- |
| SFace | 6.29 ms | 6.78 ms | 0.832 |
| EdgeFace XS | 2.22 ms | 2.25 ms | 0.843 |
| EdgeFace S | 3.26 ms | 3.41 ms | 0.898 |

每个模型预热五次，测量六十次。EdgeFace S 单次提取中位耗时约低 48%，在本次小样本上跨角度相似度更高，因此选为当前主模型。
相似度来自不同特征空间，表格不证明通用准确率排序。公开同人、异人对照也只用于基本检查，不作为误认率验收。
FaceLiVTv2、完整 AdaFace/CAFace 和更换跟踪器仍是后续对照候选，本轮未引入它们的完整运行依赖。

摄像头与人体跟踪继续工作。人脸可见性、清晰度和曝光最多每秒检查五次，身份确认且面部外观稳定后约每秒提取一次特征。
新轨迹、明显面部变化、学习姓名或手工登记恢复较高频率。检测多人会立即撤回，不等待低频定时器。
当前帧必须独立支持唯一人物，才参与最多四帧的质量加权证据。模糊、陌生人与歧义不能靠历史高分继承姓名。
这里只实现有界质量加权证据，没有声称接入完整 CAFace 网络。
失去轨迹超过 1.5 秒清理临时缩略图和证据，关闭模式或切换会话立即清空。

`recognition_templates` 保存 DPAPI 加密的 512 维特征，按人物、模型 hash 和角度隔离。
重启复用索引，新照片或姓名变化刷新索引，删除人物同时删除所有模型特征。
原 `people.template` 的 128 维 SFace 特征不覆盖。新介绍仍生成 SFace 登记模板，并从照片生成 EdgeFace 索引。
数据库更改前已保留本地可恢复备份。公开报告只含数量、模型和脱敏统计。

## 连续轨迹复核与可撤销补采（AIRI-029）

当前模型保留，按基础身份锚点、连续候选、基础再确认三步补采新条件。
已认识人物后续角度改为独立扩展，不再由单帧直接修改基础照片。明确介绍期间的登记仍保留。
仅EdgeFace索引开启本轮扩展。三个可靠基础匹配建立锚点，当前单人、连续时间/位置/外观、后续同一基础身份再次三次确认才提交。
丢失、多人、冲突、断流、版本/授权变化清空候选。扩展不能担保下一轮学习。
face_extensions按模型和观察批次保存加密向量/裁剪，最多每轮3个、每人物模型12个。
开发者记忆管理页选择人物后，可按批次撤销。人物删除同时清除扩展。

首页与视觉设置显示待复核进度，质量诊断分开模糊和曝光。诊断与暂存的跟踪状态不作为姓名或私人记忆授权。
严重失焦/曝光或没有检测到脸仍无法补采，不能靠延长姓名缓存解决。

```powershell
$env:TMP = Join-Path $AiriWorkspace '.runtime'
$env:TEMP = $env:TMP

```

独立真人录像的识别提升、换人误认与错误入库仍需AIRI-009验收。
