# 人物全部记忆清除交付报告

日期：2026-10-19。任务：AIRI-042。范围：本机 Web 人物维护、主机人物库与当前浏览器聊天档案。

## 功能与使用

开发者登录后，在记忆管理中选择人物，姓名旁可点击“清除对这个人的全部记忆”。确认框展示人物姓名、删除范围和不可撤销说明。选择取消或切换人物/角色时，原确认失效。

清除主机人物档案、照片、模板、识别扩展、姓名确认、所有角色交流与相遇。同时清除当前浏览器该人物所有角色的会话原文、收藏、标签、备注、摘要及待发送数据。按人物 ID 清理，不会按同名误删其他人物。

服务器先校验开发者权限。批准后关闭舞台，取消摄像头、音频和正在生成的对话；会话领导窗口再删除浏览器持久记录并撤销当前人物身份与其他窗口缓存。成功后显示完成，用户点击舞台“启动”即可测试重新认识、再次确认姓名与建档。再次建档获得新 ID，不继承旧人物的记忆。

两处存储不能形成同一事务；中途失败显示可能部分完成并保留重试，不伪报成功。服务关闭会撤销开发者服务端会话，后续维护需重新登录。

## 发现并修正的问题

旧按钮位于交流正文之后，只调用主机删除接口，没有清理后来增加的浏览器档案。

真实 IndexedDB 多窗口测试还发现，已安装 unstorage 驱动的 `getKeys()` 返回物理键而非命名空间内相对键。上层按前缀过滤时得到空结果，整理记录可能漏删。“删除后列表为空”的旧断言不能证明数据已删除。

存储适配现在筛选当前命名空间、去掉物理前缀。实际持久键和内容保留。回归先验证生成的原文、整理存在，再验证全部删除，并证明其他人物与陌生人数据保留。原聊天档案读写和检索测试继续执行。

## 验收边界

所有删除测试只用生成身份、临时 SQLite、真实 DPAPI 与隔离浏览器 IndexedDB；没有点击真实人物的删除确认。

实际 4173 舞台完成启动→关闭→重启，休眠时从设置进入机体模块→长期记忆。开发者管理和全量删除界面使用生成 API 档案，真正的主机删除事务由临时数据库测试覆盖。桌面与 390px 界面均检查确认区和无横向溢出。实际视觉模型服务最终恢复 ready。

尚未进行真人摄像头重新入镜、麦克风连续认识对话及真实模型话术验收。自动测试不代表人脸准确率或模型一定按确认话术回答。

清除范围只覆盖当前主机与当前浏览器来源的已归属人物数据。其他来源/设备、导出文件和私密备份需分别处理。未归属的陌生人片段不能可靠按姓名定位，保留原历史，不做猜测式删除；如测试中引用了旧陌生人片段，需单独清理对应陌生人会话。
