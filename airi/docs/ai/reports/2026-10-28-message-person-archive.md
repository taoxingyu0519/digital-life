# 人脸与登录解耦、逐消息人物归档报告

开始：2026-10-28；验证跨至2026-10-29。任务：AIRI-045。

## 已实现

原人脸短租期曾直接改变会话账户，触发历史重读、右上角姓名切换和语音停止。新增生成数据用例先复现：识别结果改变 `userId`，同一舞台中的消息也没有独立人物归属。

现在登录账户、主舞台会话和归档人物分别管理。人脸只选择消息归档对象，登录/退出继续由真实认证决定。人脸失认、短暂离开、多人或姓名确认过程不会因此切换主舞台会话、重读聊天列表或重启实时连接。有效人物证据消失时，后续消息明确标为“归属待确认”，聊天可以继续。

取得人脸登记许可后，合格单人脸先保存匿名档案、加密特征/裁剪和永久随机 UUID。角色照常聊天，早期记录可以归档到该 ID。姓名必须本人确认；确认或纠错后只更新显示名称，UUID 和早期记录保留。新增持久行为规则 `unnamed-friend`，引导适时换一种自然措辞询问名字，不每句话催问，不在拒绝后坚持。

每条用户/助手原文带 `archive` 归属。普通文字在输入派发时捕获，助手回合沿用；实时 ASR 的部分与最终转写保持一致，任务受理、结果和分段朗读也保留任务归属。中途出现另一张脸不会把原回复归给新人。归属字段保持可序列化，不携带运行时 Proxy，也不充当模型指令或登录凭据。

没有新用户输入的主动问候、摄像头发声和自动续聊按当前人物捕获。额外用例先复现：A发言后出现B，给B的主动文字/语音问候被归到A。修复覆盖会话追加与语音发言两条路径，5项相关场景通过。

`social.recipient` 与可读记忆 `profile` 分离。姓名核对可以隐藏旧记忆，但核对消息继续归到已经验证的原人物 UUID。对仍未取得档案的原具名采样路径，姓名确认后继续提示等待合格样本，不能提前声称档案完成。

主舞台气泡上方新增 10px、低强调标签，形式为“角色名-人物名”。匿名显示短 ID，无法归属时明确显示待确认。姓名目录按 UUID 更新，所以匿名阶段的旧气泡在确认名字后也可显示正确姓名。右上角账户保持原陌生人或真实登录用户。

## 数据与权限

复用现有存储：主机 SQLite 保存人物档案和有界近期交流，当前浏览器 IndexedDB 保存完整聊天原文和逐消息归属。人物“记忆库”是按永久 ID 划分的逻辑档案，没有为每个人新建数据库文件，也没有增加独立插件或外部账户。

支持会话归属和逐消息归属两种原文形式。新消息按字段过滤；没有该字段的记录沿用原会话归属，不猜测迁移或按姓名合并。检索、整理、原文上下文和导出使用同一人物过滤。开发者总览/维护继续验证已有会话，人物姓名不授予开发者或 hosted 权益。带人物归属的消息保留在本地，不进入 hosted 云同步。

“清除这个人的全部记忆”同时处理原人物分区和混合舞台会话中的目标消息与整理，保留其他人物的原文及舞台会话。对话中拒绝记忆也会撤销匿名档案及对应浏览器归档。真实数据库在加载新逻辑前已通过 SQLite backup 保存到私密忽略目录，未删除真实人物做测试。

## 验证与边界

已验证：命名/匿名/失脸之间变化时舞台 session 与登录不变，A/B 消息分别归档，部分转写中途换脸仍归原人物，名字补全后 ID 不变、标签更新，混合会话只删除目标人物，当前人物以外的档案权限与原文导出隔离。

最终交付门禁14步全部通过，自动用例共344项：联合回归18文件177项、核心聊天33项、语音/视觉协议46项、主题1项、配置宿主6项、Python81项。全部55个工作区类型检查通过，全仓lint退出0（0错误、603项既有警告），共享包及Web生产构建通过。

实际4173网关确认网页、启停同源保护、共享配置、视觉CUDA ready和语音配置连接均通过。语音网关标记 `modelAuthenticationTested: false`，这些检查没有调用付费模型完成请求，不能据配置存在声称真人听感或厂商鉴权完成。

实际 4173 舞台用隔离浏览器和生成消息验证：右上角保持陌生人、同一舞台保留四条不同人物消息、确认姓名后标签更新，桌面与 390px 无横向溢出且标签字号为 10px。真实启动→关闭→重启、休眠中设置→机体模块→长期记忆以及开发者记忆门控通过。视觉服务最终恢复 ready；页面异常为 0。

没有使用真人照片或私人对话截图。真人人脸再识别质量、麦克风多人连续对话及实际模型是否自然变换问名话术仍待现场验收。匿名档案起点为一份合格样本，不代表已测得真人准确率。完整原文仍按当前浏览器来源保存，跨设备全量原文同步、大规模档案检索性能和未归属历史的自动重标不在本轮范围。

原人物分区的逐条原文删除仍受原会话所有者检查约束，不会因认出人脸而获得修改另一个账户会话的权限；开发者全量清除可清理这些分区。新舞台会话中的目标人物消息可走现有删除路径。

首次并行根类型检查发生进程内存不足，未记为通过。交付脚本改用串行类型检查，范围保持全部工作区；当前终端 Node 堆上限为 4096MB。一次浏览器测试启动的自动审批超时，命令未执行，按工具允许重试一次后执行。没有更改沙箱或审批策略。

完整门禁曾分别被旧测试替身缺少新捕获方法、原人脸切账户断言、具名采样提示缺失阻断，均保留失败结果后修正。归属捕获最终由身份 store 的纯读取提供，不扩大 Node 编排替身。缓存 lint 在打印0错误后仍以 `-1073741819` 崩溃；改用同规则、同范围的 `--no-cache` 后退出0。没有忽略失败、修改 node_modules 或放宽规则。

组件夹具中的样式加载不稳定，等待后也可能缺少完整应用样式。组件用例最终只验证姓名和永久ID绑定；字号测量放到实际4173页面脚本，在桌面/390px均严格要求10px，同时检查标签对齐。移动标签随原气泡靠左，桌面用户标签靠右。新增断言的Element类型问题由完整类型检查发现并修正，未忽略该门禁。

后续联合运行发现姓名转写用例仅等待1秒，可能早于1Hz首帧而失败。改为等待指定陌生人的新鲜帧，最多5秒，确认、写库与通话断言不变；单项随后通过。没有提高送检频率或放宽人物新鲜度。

## 后续能力建设顺序

| 尚未接入的能力 | 建设方式 |
| --- | --- |
| 跨浏览器完整原文 | 先复用永久人物ID和消息ID设计主机原文接口、增量提交与删除确认，再接浏览器队列；不把现有配置同步冒充聊天同步 |
| 可确认的长期事实 | 从已有原文提出带来源的候选，确认后写入独立事实记录；更正与删除同时撤销索引和模型引用 |
| 长期语义检索 | 在前一步有来源和删除规则后接现有 memory-pgvector 模块，先验证召回与人物隔离，再对模型开放；当前骨架不算已接入 |
| 多人同时发言归属 | 先验证说话人与画面人物的关联，再考虑自动分配；关联未确定时继续显示归属待确认 |

上述能力本轮未启用。行为习惯继续优先保存在可维护的记忆规则；消息归属、写库、权限和删除由现有程序保证，不依赖模型自行遵守，也未新增插件。
