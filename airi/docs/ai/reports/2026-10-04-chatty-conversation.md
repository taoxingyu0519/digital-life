# 活泼话痨会话风格交付与验证

日期：2026-10-04。任务：AIRI-024。范围：本地Web既有快慢脑、会话风格和共用前端。

## 已完成

在“设置 → 模块 → 实时对话 → 会话风格”增加“活泼话痨”，保存于原风格偏好，不替换人物卡。
参考“活泼话唠模式研究”可读正文，吸收高表达、主动提供内容、低回应索取、用户贡献改变后续话题的方向。
通过具体观点、选择、联想和想象的小计划表现人物，不反复念履历、催答、空泛夸奖或要求证明喜欢。
幻想不冒充查证事实；沉默不成为用户偏好、认可或诊断。策略进入实际快脑启动/更新和后台模型请求。

自动续聊是真实运行代码：明确选择话痨并进入语音通话后，空闲约2秒且无正式任务时，已选慢脑准备一段，豆包使用原队列朗读。用户不必发送新消息才能续聊。
目标80–180字，最终JSON的speech上限300字符。只读当前角色、陌生人身份、最多16条近期确认事实及既有授权视觉文字，不挂载工具、联网或新增记忆采集。
输入是明确应用事件的system消息，不插入假的user轮次。私有分析和未播放稿件不进入下一次确认事实。

用户话音、原生回答、播放和正式任务执行/结果优先。插话取消旧准备，新确认发言改变后续内容。
换风格、模型、人物、身份、会话、视觉授权变化及挂断使旧候选失效，迟到返回不能发声。视觉撤回也清掉对应主动稿/播放。
摄像头companion保留观察和原相遇通话生命周期，在话痨通话中让出问候/闲聊，避免第二个主动循环。

首页悬浮面板增加准备状态、真实请求计数、未配置说明、重试与暂停/继续自动说话，不改变人物和输入框的布局位置。
UI及现有set_agent_delivery按用户明确要求控制自动闲聊和结果，暂停不取消正式任务；手动打断/静音后不会擅自恢复。
每通话最多30次准备请求，失败也计数，切换风格/恢复不重置预算。15秒超时或失败后停止自动重试，普通语音和任务仍可使用。
原10分钟及不自动重连规则保留。纯文字只改变风格，单选风格不启动麦克风。这些数字是工程预算，不是心理学阈值。

## 实际链路

风格 → conversationPolicy → 豆包快脑system上下文。
活动通话空闲事件 → realtime-voice调度 → slow-brain.composeContinuation → core-agent真实协议适配 → 已选模型最终JSON → schema/身份/模型/代际核对 → 原sendSpeech → 豆包speech_text_buffer.commit → 匹配音频结束且本地排空 → 确认事实 → 下一次续聊。
正式任务继续走BrainRuntime、原授权工具和权威result_summary。候选准备与取得发言权分开，没有第二个TTS或协调模型。
