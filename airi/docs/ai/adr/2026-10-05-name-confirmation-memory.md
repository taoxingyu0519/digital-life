# 姓名确认采用行为记忆与最小写库保护

日期：2026-10-05。任务：AIRI-025。范围：本机 Web 与已有视觉服务。

用户反馈语音登记姓名出现错字，希望角色先确认文字，通过对话修正，并减少独立插件。
旧实现提取姓名后立即采样保存，提示词无法撤回已经发生的数据库写入。

采用 SQLite `behavior_rules` 保存姓名确认习惯，复用当前请求的普通聊天和实时语音上下文。
不新增智能体插件、协调模型或外部数据库。
`SocialLearning` 保留轨迹范围内的候选拼写，只有明确确认后才采集登记样本或改名。
`name_confirmations` 保存本人确认结果。旧档案第一次再次相遇时补问确认，原数据保留。
改名以原人物 ID 更新，保留照片、模板、相遇和角色交流记忆。
不能确定错字时请求完整书面姓名。任意语义解释和真人同音字识别仍需后续验收。

前端记忆和数据入口接入已有仓库能力。本机开发者账号独立于 hosted 账号和社交身份。
同源代理转发 HttpOnly Cookie，Python 对每个管理请求检查一小时有效会话。
密码只保存加盐 scrypt 摘要。未认证者不能访问人物总表、管理 API 或手工登记接口。
普通聊天仍以陌生人进入。当前单人对话的有界记忆读取和本人纠错保留原归属检查。
性能统计对现有诊断脚本开放，含人物的观察仅向开发者返回。

代价是确认步骤增加一轮对话，本机视觉服务同时承担管理接口。
管理页权限限制应用入口，不能把浏览器 IndexedDB 或主机文件变成对设备所有者不可读的数据。
Electron/Pocket 没有新宿主网关，当前只验收 Web 与既有 LAN 代理。
长期事实、向量检索和跨设备同步没有在本轮实现，建设路径见中文交付报告。
